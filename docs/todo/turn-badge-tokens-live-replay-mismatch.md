# Turn 统计徽标 token 数在重启后与 live 会话不一致

> **状态**：待裁决（调研口径未定）。**来源**：2026-10-04 feat-chat-html-support D3 验收 A7 重启前后一致性对比（第二段）的过程观察。**性质**：显示层聚合口径差异，非本分支引入（观察于既有 turn 统计徽标，本设计不触碰该面）。

## 现象

同一 turn（相同起止时间）的统计徽标 token 数在 dev 实例重启前后不同（实测两组：70 → 630、294 → 832）。重启后由持久化会话 jsonl 重放聚合，live 时由流式 delta 增量聚合——两条通道的统计口径（计入哪些消息 / 是否含重试与系统开销）疑似不一致。

## 影响

- 显示层信息一致性问题：用户重启后看到同一 turn 的 token 消耗「变大」，无法区分是统计修正还是口径漂移。
- 不影响任何功能判定（徽标为观察性信息）。

## 建议方向（裁决时定案）

1. 先定性：定位 live 聚合与重放聚合两处实现，对同一会话 jsonl 跑双通道对拍（对照验证），确认差异来源（重试消息计入？系统消息计入？usage 字段取值差异？）。
2. 再裁决：统一到单一口径（倾向以重放聚合为准——持久化数据可复算、可测试；live 侧对齐），或明确记录「live 为估算值」的降级显示策略。
3. 若修复，补一条「live 与重放对同一 jsonl 聚合结果一致」的单元测试。
