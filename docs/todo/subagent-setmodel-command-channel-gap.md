# subagent.setModel 命令链路生产适配器未接线（跨端通道缺口）

状态：已解决（2026-10-07 关闭——用户裁决候选 A 落地，通道实装并经 5 轮真机验收全场景可达；机制权威 = [ADR-0128](../adr/decisions.md) 与设计 §7.1.1，下方盘点内容作通道裁决依据存档）。

**解决记录**：候选 A 实装 = U6 收尾单元（extension `/subagent-model` 命令 + runtime `SubagentModelSwitchGateway` 适配器 + 组合根注入 + prompt 出站点守卫白名单登记），requestId 结果文件回执 + 60s 超时。验收：D3 五轮真机（chat 轮内热切 / workflow 全切聚合 / 持久化延续全场景实测，终局 degraded 无阻塞缺陷，见 `.tmp/dev-flow/subagent-model-switch.acceptance/verdict.json`）。登记条款中「待设计裁决项」的落定：命令载荷 = `/subagent-model <单行 JSON>`；请求关联键 = requestId；超时 = 60s（65s backstop）；回执载体 = 结果文件（非 custom entry——jsonl 事件词表四点同步纪律只管状态机事件，覆盖记账走 `model-override` 事件帧，模型切换应答属请求-应答语义走文件通道）。

- 现状：`subagent.setModel` WS 消息的生产链路在 runtime 侧断裂——`SubagentModelSwitchGateway` 全仓无生产 `implements`（仅 `packages/runtime/src/interfaces.ts` 端口定义 + `packages/runtime/src/transport/__tests__/subagent-message-handler.test.ts` 测试 mock），组合根未注入 `subagentModelSwitchGateway`，`SubagentMessageHandler`（`packages/runtime/src/transport/subagent-message-handler.ts`）恒回 `subagent_model_switch_unwired` 可操作错误。前端入口（SubagentTab/WorkflowTab）与宿主编排本体（`packages/subagent-core/src/execution/subagent-service.ts` setModel 壳）均已就绪，缺口在两者的连接段。
- 根因（通道盘点，读码核实）：宿主编排跑在 pi 进程 extension 内（subagent-core 单例，`extensions/universal/subagent-workflow/src/session-lifecycle.ts` 装配），而 runtime → pi extension 无结构化调用通道——pi 实装版 1.0.0 的 rpc-mode 命令词表封闭（`node_modules/@earendil-works/pi-coding-agent/dist/modes/rpc/rpc-mode.js`，default 分支 = Unknown command error）；现役 slash command 通道（`client.prompt("/subagents ...")`）的 RPC reply 只含 preflight disposition、不携带 command handler 的结构化输出（rpc-mode.js prompt case）。设计文档 §7.1 只定形「请求 → 宿主 setModel → 应答」，未定义 runtime 触达 pi extension 的物理通道。
- 影响面：设计 §8 全部真机场景（1-7）在生产 dev 实例的「执行中切换」半场必以 `subagent_model_switch_unwired` 失败；记账半场（无活进程路径）同样经此入口，同受影响。覆盖状态查询链路（详情载荷 `modelOverride` / `recentEffectiveModel` 透传）已不受本缺口影响（见下）。
- 排障入口：生产 dev 实例切换模型报「subagent.setModel 尚未接线（宿主模型切换编排未注入）」即本登记所述状态，非用户操作错误。
- 接线所需（重派时的实施单元量级清单）：① runtime ↔ pi extension 的结构化调用通道协议设计（请求关联键 / 幂等 / 超时语义需设计裁决，不得在修复轮自定；候选形态可行性已探针核实，见下节）；② `extensions/universal/subagent-workflow` 侧暴露该通道消费 SubagentService.setModel；③ `packages/subagent-core/src/execution/subagent-service.ts` 生产 deps 的四个 fail-fast 桩替换（engineSetModel / runAggregate / assertRunNotTerminal / listAcceptedMemberRunIds——**已交付**：一致性修复 R1 packages-subagent-core-wiring 组 + model-switch-wiring 19 用例）；④ runtime 侧 gateway 适配器实装 + 组合根注入 `subagentModelSwitchGateway`。
- 候选通道探针结论（2026-10-06，读 node_modules 实装 1.0.0 dist 核实）：**候选 A（slash command 动词 + custom entry 回执）可行，且为本项目在产标准通道**——仓内三处先例：① workflow abort（session-records.ts:1150 `client.prompt("/workflows abort <runId>")`）；② subagent cancel/message/start（session-records.ts:1156 起 `client.prompt("/subagents <action> ...")`，extension 侧专属 RPC 分支解析 command-actions.ts parseSubagentRpcCommand，含带参动作先例）；③ plan 退出（session-service.ts:1196 `client.prompt('/plan abort')`，注释双承重记录了 pi 机制锚点与守卫豁免依据）。机器守卫 = `.githooks/check_prompt_outposts.py`（runtime 全部 `.prompt(/.steer(/.followUp(` 出站点对照白名单，未登记即红）——新哨点须登记。pi 机制面（1.0.0 dist 核实）：`prompt()` 主路径对 "/" 前缀先走扩展命令分支（`agent-session.js:1490` `_tryExecuteExtensionCommand` → `:1600-1620` 执行 handler），注释明示「execute immediately, even during streaming」、`expandPromptTemplates` 缺省 true（`:1488`）；排队路径（steer/follow_up）才拒绝扩展命令（`:1655`）。RPC 应答仅含 preflight disposition（`rpc-mode.js:309`）——结构化结果经扩展命令写 custom entry、走既有 entry 推送通道按请求关联键回收。**候选 B（上游扩展 RPC 面）不可行**：rpc-mode 命令词表封闭（`rpc-mode.js:298-439`，无扩展 RPC 注册点，改上游违反不 fork/不提 PR 约束）。待设计裁决项：命令载荷编码（args 内 JSON）、请求关联键、runtime 侧待答表超时量级、回执 custom entry 的 type 字面量（走事件词表四点同步纪律）。
- 已交付部分（同轮 fix-packages-runtime-gateway 组）：覆盖状态查询生产链路——`packages/runtime/src/services/session/model-override-query.ts`（磁盘投影查询：record 事件文件 `record-model-override` 帧 + run journal `model-override` 帧尾向读取，权威源语义与两域 fold「后写整替无清除帧」构造性等价）+ `SessionService` 装配注入（session-records deps.modelOverrideQuery）+ `projectSubagentModelDetailIntoRuns` 接线。详情载荷覆盖状态字段（标签规则分支②与重启后标签恢复通道）已生产可用；`recentEffectiveModel` 派生（U1 交付）不受影响。
