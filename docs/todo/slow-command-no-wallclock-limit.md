# 慢命令挂起无墙钟上限（进程死亡时气泡悬挂至重开 session）

状态：已实施（2026-10-05）：墙钟豁免保留（「任务级正常路径禁止自带墙钟超时」原则不变）；残余形态「进程死亡时气泡悬挂至重开 session」已由断连事件驱动的未确认终局修复——pi 断连 → 挂起在途投递批量显式失败 + message.error 逐条上报（registry onPiDisconnected，本批落地）。

- 现状：命令条目经 G3 三闸联动豁免后无墙钟上限——rpc-client prompt RPC 不限时档、内核 port.send settle 兜底（60s）对命令条目不武装、前端 30s 空窗计时器对命令条目不挂表。这是「任务级正常路径禁止自带墙钟超时、用户显式指定才生效」原则的落地：交互命令（如 /permission rule|model）挂起多久都不会被切成失败形态，挂起语义成立。
- 影响面：残余代价 = pi / runtime 进程死亡时命令条目无本地收尾、气泡悬挂至重开 session（与「命令终局凭据不留盘」「pi 重启响应丢失」两登记同族）。
- 恢复通道（现行）：进程死亡时挂起条目已显式终局（failed + 用户可见上报），用户重开 session 后自行决定重发——重发会执行第二次，先核对 transcript。
- 重审触发：出现「命令条目悬挂且用户无法辨别进程死活」的实际困扰时，重审会话级挂起指示（收尾凭据链补 pi 存活态投影，非墙钟超时）。
