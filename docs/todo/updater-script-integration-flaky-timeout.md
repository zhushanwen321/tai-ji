# updater-script-integration S1 用例负载下瞬态超时

状态：已校准关闭（2026-10-14：耗时分布实测采集完毕，预算按分布校准 15s → 30s + 超时错误携带实测耗时；再 flake 按「归因」处置）。

## 现象

`apps/electron/main/test/updater-script-integration.test.ts` 的「S1 中断（M2 脚本侧）：staging 解压完成后 kill」用例在全量跑中偶发 `waitFor 超时: staging 主二进制就位`；同文件单独复跑 23 用例全绿，该文件与被测源码零改动，非回归。

## 误读修正

原登记的「22s 预算耗尽」是 junit 用例总耗时的误读：实际 waitFor 预算当时为 15s，用例总耗时 ≈ dmg 构造（buildMinimalAppDmg，~7s）+ waitFor 超时（15s）≈ 22s。原「pnpm test 43 包并行」表述也与实际不符：根 test 脚本 `--workspace-concurrency=1` 包间串行，负载来自 apps/electron 包内 vitest 多 worker 并发。

## 耗时分布实测（2026-10-14，TAIJI_WAIT_DEBUG=1 采集，已固化为该文件观测开关）

| 场景 | S1「staging 主二进制就位」 | 同文件其他 waitFor |
|------|--------------------------|-------------------|
| 空载单文件 | 5.31s / 2.44s（两次） | 4.0-5.9s |
| 满载包级全量（89 文件 / 1381 用例并发，123s 总时长） | 3.73s | 2.0-5.9s |

满载全绿，就位耗时分布 2-6s，原 15s 预算裕量 2.5-7x。当初 flake 需 15s+ 耗时（偏离分布 2.5x+）→ 归因系统级瞬态卡顿（hdiutil 排队/换页类外部负载），非包内并发所致，缩并发/降载无法根治。

## 校准（现行）

- waitFor 默认预算 15s → **30s**（5x 实测分布上界，吸收系统瞬态尖峰；成本仅真死锁时失败报告晚 15s——成功路径立即返回）。不降载：实测证明包内并发不构成威胁。
- 超时错误消息携带实际等待时长（`等待 X.Xs > 预算 30s`）；`TAIJI_WAIT_DEBUG=1` 打印每次 waitFor 成功耗时。

## 归因（再 flake 时）

超时错误里的实测耗时直接归因：贴近 30s = 系统尖峰再现（复跑即绿，同本轮回）；数量级偏离（分钟级）= 真退化，查 hdiutil/磁盘/被测脚本变更，禁止直接放大预算。
