# 画布回推占线排队的延迟量级记录

状态：已登记（2026-10-15，源自 problem-solve-canvas D3 A3 判定书 r4 观察项）

## 事实

A3 真机重验（commit 91942e59e 后，r4 轮）实测：agent turn 占线时提交用户裁决，回推通知经 pi `streamingBehavior='followUp'` 排队，DOM 出现延迟 1944ms；agent 空闲时同链路 102ms。差量约 1.8s = 从 followUp 入队到当前 turn 结束边界的等待（turn 4 判据响应正文完整写完未被中断，排队通知在其后 6ms 注入）。

## 判定

符合 followUp 语义（不打断进行中响应，排队等 run 结束），≤2s 实时可见断言通过。**非缺陷，此处仅记录量级供后续裁决**。

## 待裁决点

若后续产品要求占线时更快感知，可选方向：steer（打断当前 turn——与「不打断进行中响应」的设计取向冲突，需先改取向）/ 通知改走与 turn 无关的 UI 通道（画布面板内提示，不进对话流）。两者都改当前已定契约，无用户抱怨前不动。
