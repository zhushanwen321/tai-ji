# 长流 delta 双计观察项（remote-use D1 不采用②）

状态：观察登记，不实施——触发条件未在真机复现前不投入；真机复现即重启方案复审。设计依据：`.tmp/tech-design/remote-use-shell-unification.md` §3.3 D1 不采用②。

## 机制

链外全量重订回放（重订对订阅失败条目不带 fromSeq，触发全量回放；回放经序号门兼容路径全量放行）落在已加载分区、且该分区含流式中轮次时：message_start 查重已防住重复气泡，但回放的 text_delta 是纯追加（chat store registry 的内容累加，无内容级去重）——已累积内容被整段重加，且流式中气泡受尾部保护段保护不被基线替换。双计内容要等轮次终结后的下一次切入/对账（reconcileHistory）才清洗。

ring 溢出形态（message_start 已被挤出 ring 而 delta 仍在）是该窗口的子形态，非触发前提。

## 症状判别

流式中气泡内容跳增（同段文本出现两遍）或出现无头 delta（新气泡只有 delta 片段、无开头）。恢复收敛事件（重连对账/再切入）后内容应回到与基线一致；终结后仍残留双计文本则超出本观察窗口，属另一缺陷。

## 不采用理由

内容级双计防御（回放期序号门扩展，`subscribeSession` 回放前置「回放中」状态供序号门判定）语义精确，但引入 subscription-state ↔ registry 跨模块状态耦合；独立价值（内容级防御）在 message_start 查重 + 终结后对账清洗已兜住正确性收敛（瞬态显示抖动除外）。
