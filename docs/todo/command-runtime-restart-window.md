# 命令终局凭据不留盘：runtime 重启窗口内命令可能重复执行

状态：已知限制显式接受（pi1-disposition-chat-flow 设计 D14①，2026-10-04 登记）。

- 现状：被 pi 接管的命令条目（disposition=handled）以 handled 即条目终局，终局凭据 = DeliveryTombstone（delivered 终态，内存态）。刻意不为命令建持久化凭据：命令执行不写会话文件（pi 1.0 命令「重放无痕」），无凭据可落盘；普通消息的 tombstone 重启后同样丢失，但普通消息靠 transcript 有痕可重投对账，命令无痕。runtime 进程崩溃重启后，重启前窗口内的命令终局凭据全部丢失，对账器对「无会话痕迹的命令」存在盲区——同一命令可能被重复执行。
- 影响面：触发需三条件叠加（runtime 崩溃 + 崩溃前窗口内命令在途 + 该命令有实质副作用），属极端场景；条件不叠加时零影响。
- 恢复通道：手动删除重复副作用（无自动恢复路径）。
- 重审触发：重复执行事故实际发生且命令副作用不可人工恢复时，重审命令持久化对账通道。
