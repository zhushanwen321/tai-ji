# 侧栏快捷键提示（⌘N / ⌘I / ⌘K）是否改按需的重新裁决（D7 移出项）

状态：维持常驻（移出 ui-signal-density 范围——代价侧答不上，本次不动；重新裁决须与控件使用频率盘点合并做）。登记来源：ui-signal-density 设计 D7「v4 移出本次范围」

## 现状

侧栏「新建任务 / 导入会话 / 搜索」三项入口各带常驻快捷键提示（`Sidebar.vue`，⌘N / ⌘I / ⌘K，绑定在 `useGlobalShortcuts.ts`，随 `sidebar.collapsed` 走 CSS 隐藏、DOM 常在）。

## 移出理由（设计原文口径）

- 三条提示是新用户发现这三个主入口的**唯一静态线索**；改悬停 / 聚焦才显后，新用户在侧栏看不到它们——「仍能通过悬停发现」的前提是先知道按钮在那儿。
- 侧栏是 300px 固定列 + 三条按钮 + 会话列表，本来就不拥挤，不是「对话流第一屏信噪比」问题的组成部分。为三处文本槽引入可达性代价，量级与收益不匹配。

## 重开条件

与 [chrome-control-usage-inventory.md](chrome-control-usage-inventory.md)（低频控件使用频率盘点）合并裁决——同一题：入口该不该常驻。若盘点数据表明老用户从不读提示、且侧栏出现真实的密度压力，可重提「悬停 / 聚焦才显 + 快捷键绑定不动」的方案；届时键盘可达性必须与悬停一翼同时做（`group-focus-within` 范式，参照对话流既有写法）。
